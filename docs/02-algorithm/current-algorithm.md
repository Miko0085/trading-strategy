# Текущий базовый алгоритм

**Статус: ПОДТВЕРЖДЁННАЯ БАЗОВАЯ МЕХАНИКА / ОТКРЫТЫЕ ПРАВИЛА РЕСТРУКТУРИЗАЦИИ**

```text
Запустить стратегию
↓
Зафиксировать текущую Mark Price
↓
Создать Long Grid и/или Short Grid
↓
Для каждого Grid Order задать:
- процентный отступ
- configured_qty
- TP Steps
↓
Выставить на Bybit заданное количество активных лимитных ордеров
↓
Получать фактические Execution / Fill
↓
Обновлять filled_qty и фактическую среднюю цену конкретного Grid Order
↓
На фактически исполненный объём выставлять реальные лимитные TP-заявки
↓
Если один Grid Order исполнился полностью или частично:
- он остаётся одной логической единицей стратегии
- следующий уровень сетки может быть выставлен, чтобы сохранить заданное количество активных ордеров
↓
По мере новых fills обновлять фактическое состояние
↓
Частично или полностью закрывать объём по настройкам
↓
Обновлять open_qty / closed_qty
```

## Активное окно сетки

Полная логическая сетка может храниться внутри платформы, а на Bybit одновременно находится только заданное число активных лимитных ордеров.

Например, если настройка — держать 5 активных заявок, то после исполнения одного уровня система выставляет следующий уровень и снова поддерживает 5 активных заявок.

## Что делает механический Execution Engine

- размещает настроенные лимитные ордера;
- отслеживает фактические fills;
- сопоставляет несколько fills с одним Grid Order;
- считает filled_qty и фактическую среднюю цену;
- выставляет лимитные TP-заявки на фактически исполненный объём;
- поддерживает заданное количество активных Grid Orders;
- принимает изменения параметров через интерфейс;
- сохраняет полную историю изменений;
- сверяет ожидаемое состояние с Bybit.

## Что он пока не решает сам

- какой объём выбрать;
- какой отступ выбрать;
- как автоматически реструктурировать сетку после разгрузки;
- как использовать общий доступный баланс и PnL при реструктуризации;
- когда приблизить TP из-за риска;
- как распределить капитал Long/Short;
- нужен ли Stop Loss;
- как должен действовать Risk Manager.
