# Execution Engine — механизм исполнения сетки

**Статус: СЛЕДУЮЩИЙ СЛОЙ ПЛАТФОРМЫ / ЕЩЁ НЕ РЕАЛИЗОВАН**

Execution Engine — отдельный компонент, не часть Recorder.

## Назначение

Он механически исполняет то, что трейдер заранее настроил в интерфейсе.

## Подтверждённая базовая механика

Execution Engine должен:
- хранить Long Grid и Short Grid;
- хранить полную внутреннюю сетку;
- держать на Bybit только заданное количество активных лимитных Grid Orders;
- считать первый уровень от Mark Price в момент запуска стратегии;
- считать следующие уровни по индивидуальным процентным отступам от предыдущего лимитного уровня;
- задавать configured_qty отдельно для каждого ордера;
- получать фактические executions;
- понимать, что несколько fills одного ордера — это один Grid Order;
- считать filled_qty и фактическую среднюю цену;
- выставлять реальные лимитные Take Profit заявки на фактически исполненный объём;
- по мере исполнения уровней выставлять следующие ордера, поддерживая заданное активное окно;
- позволять индивидуально менять параметры каждого ордера через интерфейс;
- сохранять Grid Revision и полный audit trail;
- сверять ожидаемое состояние с Bybit.

## Способ задания цены

На текущем этапе базовый режим — процентные отступы.

Каждый ордер имеет собственный процент от предыдущего уровня. Ручной ввод абсолютной цены как отдельный пользовательский режим пока не нужен.

## Take Profit

Для базовой стратегии используются реальные лимитные заявки на разгрузку, а не Market-закрытие.

Take Profit рассчитывается от фактической средней цены конкретного Grid Order / Strategy Lot и от фактически исполненного объёма.

## Изменения через интерфейс платформы

Каждая правка:
1. сохраняет старое состояние;
2. создаёт новую revision;
3. отправляет нужное изменение на Bybit;
4. сохраняет фактический результат.

Каждый Grid Order должен быть самостоятельной настраиваемой единицей, включая возможность изменять будущие Take Profit и другие разрешённые параметры в реальном времени.

## Ручное вмешательство через Bybit

Если фактическое состояние Bybit отличается от ожидаемого:
1. система уведомляет трейдера;
2. ничего не перестраивает самостоятельно;
3. после подтверждения либо принимает новое состояние, либо восстанавливает последнюю подтверждённую конфигурацию там, где это возможно без нового самостоятельного торгового решения.

Уже произошедшую сделку нельзя откатить автоматически.

## Что пока остаётся открытым

- если Entry Grid Order получает дополнительные fills после того, как TP-заявки уже выставлены, нужно ли увеличивать существующие TP quantities или создавать дополнительные TP orders;
- можно ли менять configured_qty самого Entry Order после начала частичного исполнения;
- точная автоматическая логика реструктуризации после разгрузки;
- использование общего доступного баланса и PnL при реструктуризации;
- Stop Loss и будущий Risk Manager.
