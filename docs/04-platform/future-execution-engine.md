# Execution Engine — механизм исполнения сетки

**Статус: СЛЕДУЮЩИЙ СЛОЙ ПЛАТФОРМЫ / ЕЩЁ НЕ РЕАЛИЗОВАН**

Execution Engine — отдельный компонент, не часть Recorder.

## Назначение

Он механически исполняет то, что трейдер заранее настроил в интерфейсе.

Он не должен:
- прогнозировать рынок;
- выбирать направление;
- сам придумывать объём;
- сам придумывать отступы;
- сам менять стратегию по внешним сигналам.

## Что он должен уметь

- хранить Long Grid и Short Grid;
- хранить любое нужное количество Grid Orders;
- задавать `configured_qty` для каждого ордера;
- считать первый уровень от Mark Price;
- считать следующие уровни от предыдущего лимитного уровня;
- отправлять лимитные заявки на Bybit;
- получать фактические executions;
- понимать, что несколько fills одного ордера — это один Grid Order;
- после полного исполнения создавать Strategy Lot;
- считать фактическую среднюю цену исполнения;
- хранить `remaining_qty` и `closed_qty`;
- хранить и изменять TP Steps;
- сохранять полную историю изменений;
- сверять ожидаемое состояние с Bybit.

## Изменения только через интерфейс платформы

Управляемые системой изменения Grid, Order, Qty и TP должны происходить через интерфейс платформы.

Каждое изменение:
1. сохраняет старое состояние;
2. создаёт новую revision;
3. отправляет нужное изменение на Bybit;
4. сохраняет фактический результат.

## Ручное вмешательство через Bybit

Если трейдер изменил что-то напрямую в терминале Bybit, например:
- передвинул лимитный ордер;
- изменил объём;
- отменил ордер;
- вручную закрыл часть позиции;
- полностью закрыл позицию,

система не должна автоматически перестраивать стратегию.

Схема реакции:

```text
Обнаружено расхождение
↓
Уведомить трейдера
↓
Получить подтверждение
↓
Либо принять внешнее изменение
Либо восстановить настройки платформы
```

### Принять внешнее изменение (Adopt external state)

Трейдер подтверждает, что действие было намеренным.

После этого:
- фактическое состояние Bybit признаётся новым;
- трейдер корректирует настройки платформы;
- создаётся новая revision;
- история до и после сохраняется.

### Восстановить настройки платформы (Restore platform state)

Если изменение было случайным, система может восстановить последнюю подтверждённую конфигурацию там, где это технически возможно.

Важно: уже произошедшую сделку нельзя «откатить». Если возврат к прежнему состоянию потребовал бы открыть новую позицию, система не делает этого автоматически.

## Что пока остаётся открытым

- что делать, если Grid Order исполнился только частично и остаток потом отменён;
- как именно выставлять TP на бирже: заранее лимитками или по достижению уровня;
- можно ли менять `configured_qty` после начала частичного исполнения;
- поддерживать ли ручной ввод абсолютной цены наряду с процентным отступом;
- от какой Mark Price считать первый уровень при полной перестройке сетки.
