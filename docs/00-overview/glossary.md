# Глоссарий

Ниже используются русские определения с английским техническим термином в скобках.

| Термин | Простое определение |
|---|---|
| **Ордер сетки (Grid Order)** | Один лимитный ордер внутри Long- или Short-сетки. |
| **Настройка ордера сетки (GridOrderConfig)** | То, что трейдер хочет выставить: цена/отступ, заданный объём, Take Profit и другие параметры. |
| **Биржевая заявка (Exchange Order)** | Реальный ордер, отправленный на Bybit. |
| **Исполнение (Execution / Fill)** | Фактическая покупка или продажа части либо всего объёма биржевой заявки. Один ордер может исполниться несколькими частями. |
| **Заданный объём (configured_qty)** | Полный объём монет, который трейдер задал для конкретного ордера сетки. |
| **Исполненный объём (filled_qty)** | Объём, который биржа фактически уже исполнила. |
| **Оставшийся объём позиции (remaining_qty)** | Объём Strategy Lot, который ещё не закрыт. |
| **Закрытый объём (closed_qty)** | Суммарный объём Strategy Lot, который уже был закрыт. |
| **Strategy Lot (отдельный объём стратегии)** | Внутренняя сущность, которая создаётся после полного исполнения конкретного Grid Order и дальше управляется отдельно от общей средней позиции Bybit. |
| **Частичный Take Profit (Partial TP)** | Закрытие только части Strategy Lot на заданном уровне прибыли. |
| **Этап Take Profit (TP Step)** | Один конкретный уровень частичного закрытия: цена/процент движения и доля объёма. |
| **Частичная разгрузка (Partial Unloading)** | Досрочное или плановое закрытие части объёма для фиксации результата и высвобождения маржи. |
| **Long Grid** | Сетка лимитных ордеров для набора Long. |
| **Short Grid** | Сетка лимитных ордеров для набора Short. |
| **Hedge Mode** | Режим Bybit, в котором Long и Short по одному активу могут существовать одновременно. |
| **Mark Price** | Расчётная цена Bybit, от которой в базовой механике задаётся отступ первого ордера сетки. |
| **Отступ (Spacing / Distance)** | Расстояние между ценовыми уровнями сетки. |
| **Версия сетки (Grid Revision)** | Снимок настроек сетки в конкретный момент времени. Каждая значимая правка создаёт новую версию. |
| **Фактическое состояние (Machine Truth)** | Что реально произошло на Bybit: заявки, исполнения, позиции, баланс и т.д. |
| **Намерение трейдера (Trader Intent)** | Что трейдер собирался сделать и какие параметры настроил в интерфейсе. |
| **Объяснение трейдера (Trader Reasoning)** | Почему трейдер принял конкретное решение. |
| **Сверка состояния (Reconciliation)** | Сравнение того, что ожидает платформа, с тем, что реально находится на Bybit. |

Названия полей в коде и API могут оставаться на английском, но в пользовательской документации рядом должно быть понятное русское объяснение.
