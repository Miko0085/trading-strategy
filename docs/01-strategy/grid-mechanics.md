# Grid Mechanics

**Статус: TRADER EXPLANATION / CANDIDATE**

## Тип ордеров

Grid Orders — это **LIMIT ORDERS**.

## Точка отсчёта первого уровня

Первый order может задаваться относительно reference/current price.

```
Current Price = 100
Order #1 = -10%
Limit = 90
```

## Расчёт следующих уровней

Следующие orders рассчитываются **относительно LIMIT PRICE предыдущего ордера**, а не от исходной reference price, и **не ждут фактического fill** предыдущего ордера.

```
Order #1 = 90

Order #2: -5% от Order #1  = 85.50
Order #3: -3% от Order #2  = 82.935
Order #4: -1.5% от Order #3 ≈ 81.691
```

Проценты `-10% / -5% / -3% / -1.5%` — **только пример**, не зафиксированное правило. Каждый spacing должен быть конфигурируемым. Искусственного hard limit на количество ордеров в сетке нет.

## Глубина сетки (наблюдения)

`TRADER EXPLANATION` (verified, trader_notes #7): «Размещение Лонг ордеров до минус 30% от текущей цены» — отсчёт от цены входа (уточнено трейдером в чате): дистанция между уровнями хеджа должна обеспечивать прибыльность независимо от того, по какой цене реально наберётся позиция.

`CONTRADICTION`: на реальных данных глубина не воспроизвелась как константа — один цикл дошёл до -29.3% от входа, второй до -41.2%. См. [05-research/contradictions.md](../05-research/contradictions.md).

## Sizing (объём по уровням)

Более глубокие ордера **могут** иметь больший coin quantity — качественно наблюдается на обеих известных Long-сетках (UAIUSDT), но точная sizing function не подтверждена.

**Не фиксировать** `qty × 2` или любой другой множитель как правило — если такое встречается в данных, это `EXAMPLE / CANDIDATE`, не `CONFIRMED`. Подробности и числа — [05-research/candidate-rules.md](../05-research/candidate-rules.md).
