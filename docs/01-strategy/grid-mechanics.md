# Grid Mechanics

**Статус: CONFIRMED mechanics / OPEN parameters**

## Grid Orders

Grid Orders — **LIMIT ORDERS**.

Каждый уровень сетки является отдельной конфигурируемой сущностью. Для каждого уровня могут отдельно задаваться:

- distance / limit price;
- original_qty в монетах;
- набор partial TP;
- состояние active/cancelled;
- в будущем — дополнительные параметры, если они будут подтверждены.

## Первый уровень

Первый Grid Order может задаваться относительно стартовой/reference price.

Синтетический пример:

```text
Reference Price = 100
Order #1 = -10%
Limit Price = 90
```

`-10%` здесь только пример.

## Следующие уровни

**CONFIRMED:** цена следующего Grid Order может рассчитываться от **limit price предыдущего Grid Order**, не дожидаясь его исполнения.

Синтетический пример:

```text
Order #1 limit = 90
Order #2 = -5% from 90     -> 85.50
Order #3 = -3% from 85.50  -> 82.935
Order #4 = -1.5% from 82.935 -> 81.691
```

Проценты выше не являются правилами стратегии. Они показывают только механику последовательного расчёта.

## Spacing

Spacing должен быть configurable per order.

Не считать универсальными правилами любые встречавшиеся примеры вроде:

- -10%;
- -5%;
- -3%;
- -1.5%;
- -30% общей глубины.

Фиксированной функции spacing пока нет.

## Количество уровней

Модель данных не должна иметь искусственного маленького hard limit на количество Grid Orders. Реальное число уровней задаётся конфигурацией стратегии.

Это **не означает**, что стратегия обязана использовать большое количество ордеров или что глубина сетки неограниченна по риску. Ограничения капитала относятся к будущему Risk Manager.

## Sizing

Более глубокие Grid Orders могут иметь больший coin quantity, однако универсальная sizing function пока не подтверждена.

Не фиксировать как правило:

- qty × 2;
- фиксированный martingale multiplier;
- конкретную прогрессию.

## Изменение сетки

Трейдер должен иметь возможность отменять и перенастраивать ещё не исполненные Grid Orders.

Автоматические правила перестройки сетки пока не определены.
