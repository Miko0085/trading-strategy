# Механика сетки

**Статус: ПОДТВЕРЖДЁННАЯ БАЗОВАЯ МЕХАНИКА / ОТКРЫТЫЕ ПРАВИЛА РЕСТРУКТУРИЗАЦИИ**

## Ордера сетки

Ордера сетки (Grid Orders) — это **лимитные ордера (Limit Orders)**.

Для каждого уровня трейдер отдельно задаёт:
- процентный отступ;
- заданный объём в монетах (`configured_qty`);
- уровни Take Profit;
- долю закрытия на каждом уровне.

## Первый ордер

При запуске стратегии фиксируется текущая **Mark Price**.

Первый Long-ордер ставится ниже неё на заданный процент.

Первый Short-ордер ставится выше неё на заданный процент.

## Следующие уровни

Каждый следующий ордер имеет собственный процентный отступ от предыдущего лимитного уровня.

Пример:

```text
Mark Price при запуске = 100
Long Order #1: -10% → 90
Long Order #2: -10% от 90 → 81
Long Order #3: -20% от 81 → 64.8
```

Проценты здесь только пример. Каждый Grid Order настраивается индивидуально.

На текущем этапе базовый способ задания цены в интерфейсе — **процентный отступ**. Ручной ввод абсолютной цены как отдельный режим пока не нужен.

## Объём

Объём каждого Grid Order задаётся вручную отдельно в монетах.

Автоматической формулы sizing сейчас нет.

## Частичное исполнение

Если один лимитный Grid Order исполняется несколькими частями из-за ликвидности, он всё равно остаётся **одним логическим Grid Order**.

Алгоритм должен учитывать фактически исполненный объём (`filled_qty`) и использовать именно его для расчёта разгрузки.

## Сколько лимитных ордеров держать на бирже

Полная логическая сетка может быть больше, чем количество одновременно выставленных заявок.

Трейдер задаёт, сколько активных лимитных Grid Orders система должна постоянно держать на Bybit, например 3, 4 или 5.

По мере исполнения одного уровня система выставляет следующий уровень из внутренней сетки, чтобы сохранять заданное количество активных лимитных ордеров.

Количество активных заявок — настраиваемый параметр, не фиксированное число 5.

## Изменение сетки

Неисполненную лимитную заявку можно передвинуть, изменить, отменить или заменить другой конфигурацией.

После фактического исполнения уже нельзя «отменить» совершившуюся сделку. Дальше управление относится к фактически набранному объёму.

## Реструктуризация

Трейдер вручную использует повторное выставление объёма после разгрузки на более выгодных уровнях, чтобы улучшать среднюю цену.

Полная автоматическая формула реструктуризации пока **не подтверждена**. В частности, ещё прорабатывается использование общего доступного баланса, PnL и состояния аккаунта.
