# Состояние разработки Recorder

> **Важно:** этот файл описывает только технический статус **Recorder** (`src/recorder/`). Он не является статусом разработки Execution Engine, стратегии или Risk Manager. Их состояние ведётся отдельно в `docs/06-development/`.

Ниже сохранена история технических исправлений Recorder, начиная с 2026-09-16.

Версия кода: 0.2.0. Схема: additive v3, реализована в `src/recorder/storage/migrations.py`.

## Дополнение: funding execution не считается сделкой

Bybit `execution` с `execType=Funding` теперь получает отдельное человекочитаемое описание «начисление funding (не сделка)» и не форматируется как обычный Buy/Sell fill. Для Telegram добавлен независимый флаг `telegram.notifications.funding`, выключенный по умолчанию; включённые `executions` больше не вызывают funding-уведомления. Исходное событие и нормализованные данные продолжают сохраняться.

После загрузки актуальной документации из GitHub и восстановления локальных изменений без конфликтов весь набор из 94 тестов проходит. `ruff check` проходит; `ruff format --check` отдельно сообщает о пяти неотформатированных файлах, включая файлы из GitHub и текущей локальной доработки. Рабочая БД и связи пояснений не изменялись.

## Дополнение: пустой watchlist, отключаемый raw kline и остановка «плоских» авто-монет

Три независимых изменения по итогам разбора живого recorder:

- `symbols.yaml` теперь может содержать `symbols: []` (раньше схема требовала минимум один символ, что противоречило документированному auto-discovery-only режиму и делало текущий рабочий конфиг невалидным при перезапуске).
- `market.save_open_kline_updates_raw` стал реальным bool-флагом (раньше был `Literal[True]`, не читался кодом). При `false` RAW не пишет неподтверждённые (`confirm=false`) kline WS-обновления — на них приходилось ~74% объёма RAW в наблюдаемом дампе. Нормализация и `save_closed_klines` не затронуты: неподтверждённые свечи и раньше отбрасывались на уровне ingestion.
- Для монет, обнаруженных автоматически (не из постоянного `symbols.yaml`): при подтверждённой нулевой позиции (наблюдался снимок size=0) и отсутствии активных ордеров Public WS-подключение останавливается. Запись в `tracked_instruments` не удаляется, добавлено поле `stopped_at`; новое account-событие по монете снимает остановку. Отсутствие снимка позиции трактуется как «неизвестно», не как «плоско» — монета не останавливается до первого реального наблюдения. Постоянный watchlist не затрагивается.
- Побочно исправлен порядок `ADDITIONS`/`SCHEMA_V3` в `sqlite.py`: `ALTER TABLE tracked_instruments ADD COLUMN stopped_at` раньше выполнялся бы до создания таблицы на свежей БД. Теперь additive-колонки применяются двумя проходами (до и после `SCHEMA_V3`).

Проверено: 71 офлайн-тест (было 66), включая `is_flat`/`stop_tracking`/реактивацию, полный цикл `AutomaticMarkets` (подключение → флэт → остановка → новое событие → переподключение), пропуск неподтверждённых kline из RAW при сохранении confirmed-события, пустой `symbols` в `SymbolsConfig`. По явному запросу пользователя также правлены `config/symbols.yaml` (пустой список вместо невалидного `symbols:`) и `config/recorder.yaml` (`save_open_kline_updates_raw: false`); рабочая БД не редактировалась. Live-перезапуск recorder с новым конфигом в рамках этой сессии не выполнялся.

## Дополнение: монеты без предварительной настройки

Убран watchlist-фильтр account events. REST-история запрашивается по категории без symbol, текущие linear-ордера/позиции — по USDT/USDC; для известных инструментов дополнительно читаются нулевые позиции. Checkpoint привязан к новой области сверки. Реестр инструментов сохраняется в БД, новые рыночные подписки добавляются отдельно от постоянного watchlist, после подключения/reconnect запускается настроенный backfill. В manifest включены обнаруженные монеты, в `/status` — число автоматических рыночных подключений.

Проверено: 66 офлайн-тестов, включая монеты вне YAML, повторную сверку без дублей executions, rollback обнаружения вместе с событием, восстановление реестра после открытия БД, автоматическую подписку/backfill и изоляцию snapshot другой категории. Сетевые live-тесты этой функции не выполнялись; работающий recorder в рамках этого изменения не перезапускался. Рабочая БД, заметки и их связи не редактировались. Следующий шаг — штатный перезапуск и проверка событий новой монеты при обычной торговле.

Ограничения: один рынок/category для REST и Public WS; отдельный WS на обнаруженную монету; исторические инструменты автоматически не исключаются. Gap `market_before_discovery` сохраняет факт отсутствия точных прежних котировок, даже после загрузки свечей. Остальные разделы ниже — результаты предыдущих этапов, а не новый live-аудит.

## Дополнение: связка пояснение → событие

Исправлено обновление before/after при relink: оно атомарно со сменой ссылок и сбросом подтверждения, исходный at_note_time сохраняется. Добавлена история прежних event_contexts внутри context_json (без изменения SQLite-схемы). Разделены event/general confirmations, старые кнопки проверяют ревизию и тип подтверждения. Старые пользовательские подтверждения и ссылки не мигрируются автоматически.

После исправления: 59 тестов проходят, Ruff без ошибок. Покрыты rollback relink, новые before/after, сохранность исходного контекста, явное подтверждение общего пояснения и отклонение устаревшей кнопки. Работающая БД не редактировалась; изменения применятся после перезапуска процесса.

## Что изменилось

Исправлены преждевременные commits внутри repository methods: теперь они подчиняются внешней транзакции сообщения. RAW остаётся отдельной предшествующей записью — общей транзакции между JSONL и SQLite нет; разрыв обнаруживается через provenance/verifier и ремонтируется replay в отдельную БД.

Writer продолжает обработку после ошибки одного сообщения. При фатальной ошибке освобождаются ожидающие producer futures; supervisor останавливает сбор. Нормальная остановка дожидается принятых записей.

Reconciliation подключена к startup, каждому успешному reconnect и таймеру; cursor pagination и overlap используются для получения истории. При ошибке checkpoint не продвигается. Неопровержимая полнота промежуточных состояний не заявляется.

Telegram/STT используют сохранённые заметки, ревизии, очередь повторов и outbox. Сбой доставки не удаляет завершённую расшифровку. Доставка at-least-once: если сеть оборвалась после фактической отправки, повтор может продублировать сообщение.

Экспорт — снимок SQLite, все таблицы Parquet, RAW, аудио, конфигурация и manifest. При параллельном сборе RAW может быть надмножеством SQLite-снимка; verifier отмечает ещё не проиндексированные captures. Для наиболее чистого итогового экспорта сначала остановите сбор.

## Существующая рабочая БД

Проверялась только на чтение, без миграции или исправления её содержимого. На момент проверки:

- пять записей reconciliation со статусом, отличным от ok, либо без статуса;
- старая схема без data-gap audit;
- нет закрытых свечей: непрерывность рынка не подтверждена.

Это WARNING по фактическим данным, а не успешный live-тест новой версии. `.env`, оригинальные RAW и аудио не редактировались. При первом запуске обновлённой версии будет создан backup и выполнена additive migration.

## Ограничения, которые нельзя исправить выдумыванием данных

- Биржа может не предоставлять всю историю состояний за disconnect; старые snapshots нельзя достоверно реконструировать задним числом.
- Snapshot — последняя наблюдаемая котировка с timestamp/age, не точная синхронизация двух WS.
- Агрегация сетки/partial close — описательный heuristic; границы одного решения требуют подтверждения трейдера.
- Before/after отражает порядок получения recorder, а не глобально упорядоченную биржевую транзакцию.
- Старые строки остаются доступными, но новые аналитические проекции автоматически не заполняются предположениями.
- Verifier проверяет внутренние gaps свечей и gaps запрошенного backfill; полнота произвольно заданного исторического эксперимента требует явного окна сбора и проверки его границ.
- Backup и RAW не имеют автоматической retention-политики: свободное место нужно контролировать.
- SQLite lease использует `fcntl`; Windows не проверялся.
